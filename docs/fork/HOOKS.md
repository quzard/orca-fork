# Fork hooks

These hooks are the only intentional edits to upstream files. `src/fork/register.ts` is imported by the main process and the renderer and registers the host-directory sidebar without importing Electron. Main-process modules register from `src/fork/register-main.ts`, called by `src/main/index.ts` before preflight and by `startOrcad`. The file secret store registers from `src/fork/register-electron.ts`, called only by the Electron main process, so orcad does not load Electron. Renderer modules register from `src/fork/register-renderer.tsx`, called by `src/renderer/src/main.tsx` immediately after `registerForkModules()`. Until that registration runs, every hook keeps the upstream behavior: no extra await, no extra DOM, no extra menu row, no change to persisted values.

Built-in ids are refused by the registries, so a registration cannot replace Project, Status, PR, or None grouping, and cannot replace the Electron secret store unless `registerDesktopSecretStore` is called.

Paired clients still validate `groupBy` with the upstream Zod enum. A desktop-only mode survives in the desktop profile store. The phone keeps its previous mode if it sees an id it does not know.

`registerForkModules` is called from `src/main/index.ts` (before preflight) and `src/renderer/src/main.tsx`. `registerForkMainModules` is called from the same main entry and from `startOrcad`. `registerForkRendererModules` is called from the renderer entry and also registers the history-list slots. The web typecheck include lists `src/fork/**/*.tsx` so those modules are part of the renderer project. The main-process project includes `src/fork/**/*.ts` except sidebar modules that import the renderer. Node-only fork files are excluded from the web project.

`sidebarGroupId` on a workspace is an optional wire field (`string | null`). Older peers drop unknown fields, so a refresh that omits the field must not clear a group the desktop already has. `null` still means ungrouped. A missing field on a workspace that has no saved id inherits the repo or folder group when that group belongs to the same host. An old remote still cannot store the field itself; the desktop keeps it across that refresh.

Registries live in `src/shared/fork-hooks/` so main, renderer, and CLI can share them without importing Electron. Do not import Electron from `register.ts`; the renderer loads that file too. A main-only factory should `import()` Electron inside the factory, not at module scope.

## F024 retired

F024 is retired. Upstream already exports `ORCA_CLI_COMMAND` in SSH terminals, so installed skills stay on `https://github.com/stablyai/orca`. `src/shared/agent-feature-install-commands.ts` matches upstream. There is no skill-repository hook and no `ORCA_FORK_SKILLS_SOURCE`.

A fork build’s own commit is not on that repository. Skill install, skill update, and `orca skills` therefore clone the upstream base recorded in `src/fork/skills-source-commit.ts`. `fork/scripts/sync-skills-source-commit.mjs` rewrites that pin after each sync: merge-base with `fork/base-upstream`, then `upstream/main`, then the checked-in pin. Evidence for the SSH CLI path is in [skill-update-flow.md](skill-update-flow.md).

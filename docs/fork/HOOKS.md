# Fork hooks

Hooks are the only intentional edits to upstream files. A hook is a small registry in `src/shared/fork-hooks/`: upstream code calls it, and the fork registers behavior from `src/fork/`. Until a registration runs, every hook leaves upstream behavior exactly: no extra await, no extra DOM, no extra menu row, no change to persisted values. The rules for touching upstream files (hook calls only, no moved or re-indented upstream code, the `max-lines` first line and its baseline entry, fork tests in `src/fork`) are in [FORK-CHANGES.md](../../FORK-CHANGES.md) under 上游文件规则; behavior details are in its feature sections. File names below are unique in the repo unless a directory is shown.

## Upstream files changed without a fork call

- `worktree-list/drag/groups.ts`, `worktree-drag-units.ts`: a header-less section gets its own drag group.
- `worktree-set-method.ts`: passes `sidebarGroupId` and `clearFields` to the write.
- `startup-ui-hydration.ts`: the error fallback uses the registered default `groupBy`.
- `updater-check-failure.ts` (abstract `keepForkStagedUpdate` and its early return), `updater-handler-context.ts` (three optional fork callbacks).
- `SshTargetStatusRow.tsx`: two `whitespace-nowrap` classes.
- `build-mac-local.mjs`: extra arguments become electron-builder targets after `--mac`.
- `config/max-lines-baseline.txt`: the fork block at the end, after `# fork: hook lines in upstream files at the cap`, lists the four upstream files whose first line is the `max-lines` disable.
- Types and generated output: `sidebarGroupId` on `Worktree`, `WorktreeMeta`, `FolderWorkspace` and `FolderWorkspaceUpdates`; `directoryLabel` on `WorktreeRow`, `WorktreeCard` and its model; `worktreePath` on `ProjectGroupImportProjectResult`; `sidebarGroupId` on `WorktreeCreationRequest`; `code` on the `updateWorktreeMeta` failure; `'ego-lite'` in `BrowserSessionProfileSource`; the fork RPC names in `rpc-params-catalog.generated.ts`; the version in `package.json`.

## TypeScript projects

- The node project includes `src/fork/**/*.ts`. Fork code that imports the renderer is `.tsx`, so the node project never sees it.
- Main-process-only fork code lives under `src/fork/main/`. The web projects exclude `src/fork/main/**` and `src/fork/**/*.fork.test.ts` (node tests); renderer fork tests are `.fork.test.tsx`.
- tsc reports TS6307 when a fork file pulls in a file its project does not include. `src/fork/tsconfig-boundaries.fork.test.ts` runs `src/fork/tsconfig-boundaries.mjs` in the fork tests.

# 历史会话

界面和扫描行为都挂在已有扩展点上。上游的扫描协调器没有改。下面的数字来自本机 Linux、Node 24，对合成 JSONL 的一次测量，路径是 `/data/host-N/repo-N/app`，不是某台真实机器上的会话。

## 扫描时间

合成集：中等 400 个会话、每份 24 条记录、工具输出 128 KiB；大集 800 个会话、40 条记录、工具输出 256 KiB；8 台主机各 180 个会话并行。旧实现的“先返回”是等 150 毫秒，到点还没扫完就交回空列表。

| 场景                        | 上游               | 旧的 150 毫秒提前返回                        |
| --------------------------- | ------------------ | -------------------------------------------- |
| 400 会话，冷扫描            | 199 ms，有会话     | 150 ms，0 条；扫完 167 ms                    |
| 400 会话，热扫描 / 再刷一次 | 11 ms / 8 ms       | 不需要单独缓存                               |
| 800 会话，冷扫描            | 543 ms，有会话     | 150 ms，0 条；扫完 523 ms                    |
| 800 会话，热扫描 / 再刷一次 | 13 ms / 13 ms      | 不需要单独缓存                               |
| 8 台主机并行，1440 会话     | 336 ms；再刷 24 ms | 每台主机各扫各的，上游进程内缓存已经覆盖再刷 |

冷扫描时提前返回拿不到列表，热扫描上游已经是大约 10 毫秒。所以这次不另做主机缓存，刷新仍走上游的后台扫描和进度条。扫描中是上游刷新按钮的转圈和「Scanning sessions」，fork 不另显示扫描提示和主机数量。

## 界面

- 主机菜单默认是“所有主机”：本机加上已保存的运行时环境（托管 orcad、配对的服务器）。直连 SSH 的工作区上游不扫会话历史。
- 同一目录下不同主机分成两组。多台主机时先有可折叠的主机行（名字取自主机菜单，带会话数），下面是该主机的完整目录；目录标题换行，不再只留最后两段。只有一台主机时不重复主机行。
- 侧栏里新出现的主机行和目录默认收起；`/resume` 的对话框保持上游的展开。标题栏的按钮一次收起本面板的主机和目录。
- 全文搜索保持原来的命中顺序，不按主机重新分组。多台主机的命中在行上标出来源，由上游 #31261 提供（环境名和 i18n 提示）。
- 面板里不显示索引状态和主机数量，也没有单独的扫描提示，和上游一样。没有会话、不是当前工作区所在、没连上、也不是当前选中的主机收在「其他已配置主机」里。
- 工作区归属用上游的别名匹配（#35052），fork 不再改。

## 扫描进程

- 子进程堆内存：2 GiB 机器 384 MiB，4 GiB 机器 1024 MiB，16 GiB 及以上 2048 MiB。未登记时仍是 384。
- 工具输出按约 8000 字分块进索引，不再只留前 3072 字。索引版本在上游之上 +1（上游现在是 8，fork 是 9），打开时会丢掉旧库重建。
- 启动时浏览器分区的代理在后台应用，第一个窗口不再等它。

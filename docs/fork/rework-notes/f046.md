## 设计

原则：工作区外的主机文件一律经主机的单文件授权读（`files.resolveTerminalPath` 不带 `crossWorkspace`，再 `files.readTerminalArtifact*`）。授权由主机按自己的磁盘解析，规范路径绑定在授权上，所以永远读不到这台 Mac 的同路径文件。不记状态：没有 localStorage 标记、没有记下的预览位置表，重启后的标签和文档预览都按同一规则重新拿授权。

两个钩子文件：

- `src/shared/fork-hooks/host-file-doc-preview.ts`。渲染进程由 `src/fork/terminal/host-file-doc-preview.tsx` 的 `registerHostFileDocPreviews` 登记（`register-renderer.tsx`）；主进程读取由 `src/fork/main/register-electron.ts` 登记 `src/fork/main/host-file-doc-preview-read.ts`（只在桌面，orcad 不登记）。
  - `previewsHostFiles()`：`getWorkspaceFilePreviewPlan` 对运行时工作区外的路径不再拒绝，返回文档预览（网页客户端仍是上游拒绝）。终端链接里带授权的 HTML 也进上游的 HTML 分支。地址栏手贴的工作区外绝对路径和 `file://` HTML 由上游的地址栏解析直接变成文档预览，不再需要地址栏专用钩子。
  - `hostFileDocLocation`：`buildDocPreviewGrantRequest` 在上游返回 null 的那一行给出授权位置：owner 是点击时工作区（真实的 `worktreeRoot` 和选择器），`requestBase` 和 `root` 都是文档目录，入口是文件名。和上游给 SSH 工作区外文档的做法一致：只放行入口文件；同目录或子目录的 CSS、图片由上游的「这个预览想读取 … 里的文件」提示放行；`..` 以上不可达。
  - `readHostDocPreview`：`readDocPreviewFile` 在上游「运行时读不到工作区外」返回 404 的那一行调用。只处理入口在 `worktreeRoot` 外面的运行时授权，其余返回 null。先用主机给出的规范路径跑上游的 `resolveCanonicalDocPreviewPath`，文档旁边指向别处（比如 `~/.ssh/id_rsa`）的软链读不到；再用这份文件自己的授权 `files.readTerminalArtifactPreview`。上限沿用授权读取：文本（HTML、CSS、JS）512 KiB，超过是 413；图片和 PDF 受一次 RPC 回复约 3 MiB；字体等不可预览的二进制是 415。
  - `hostFileDocFolder`：文件夹提示里「.」显示文档目录，不是点击时工作区的根（上游对工作区外文档会显示错的目录）。
  - `readHostDocumentResource`：`readRuntimeFilePreview` 读 `document-resource`（Markdown 预览、富文本里的图片）而图片在工作区外时，走主机授权，和上游对 `chat-image` 的处理一样。
- `src/shared/fork-hooks/kept-host-file-view.ts`，由 `src/fork/terminal/kept-host-file-view.tsx` 的 `registerKeptHostFileViewHooks` 登记。
  - `keepHostFileInClickedWorkspace`：`resolveHostWorkspaceFile` 收到「另一个工作区拥有」时（不是目录，不是工作区根，点击的不是浮动终端），为点击时的工作区向同一台主机要一份授权，返回只读的授权结果。上游后面的路由就把它当工作区外文件：留在点击时的工作区，不激活归属工作区，不跳到已打开的同路径标签；HTML 走上面的文档预览。主机不给（#33958 之前的主机只授权终端打印过的路径）就返回 null，保持上游的切换。悬停判断链接是否存在也会经过这里，代价是对别的工作区里的路径多一次授权请求，结果进上游的存在缓存。
  - `isKeptHostFileView`：编辑器加载器在把绝对路径标签重挂到归属工作区前判断。只读、带运行时 id、按绝对路径命名的标签不重挂，读取走上游的授权续期（`readHostFileOutsideWorkspaces`）。这类标签只有这条钩子和旧主机的只读授权会产生；后者若之后被新加的工作区认领，也会留在原处只读，不再挪过去。

## 手工验证（x86_64 Linux 容器，经 SSH 部署的托管 orcad）

准备：装这一版桌面；SSH 主机连上并部署或更新托管服务器到同一版（旧 fork 的 orcad 不认无 `crossWorkspace` 的工作区外授权，工作区外 HTML 会 404、别的工作区的文件会切走，属于优雅退化）。主机上两个工作区 A（例如 `~/wt/app`）、B（`~/wt/lib`），工作区外放：`~/notes/plain.txt`、`~/notes/doc.md`（含 `![](img/chart.png)`）和 `~/notes/img/chart.png`、`~/pages/report.html`（样式写在页内）、`~/pages/site.html`（引用 `style.css` 和 `img/a.png`）及这两个文件、`~/pages/leak.css`（软链到 `~/.ssh/id_rsa` 或另一个工作区外文件）、`~/pages/huge.html`（大于 512 KiB）、`/tmp/same.txt`（Mac 和服务器上都有、内容不同）。

1. A 的终端 `echo ~/notes/plain.txt` 的绝对路径，Cmd 点击：A 里编辑器打开服务器内容，A 仍是当前工作区；能保存（上游新主机的授权可写）。
2. `/tmp/same.txt`：显示服务器上的内容，不是 Mac 的。
3. `cd ~/notes && ls` 后点 `plain.txt`（相对 cwd），以及 `printf '\e]8;;file:///home/<u>/notes/plain.txt\e\\link\e]8;;\e\\\n'`：同 1。`~/notes/plain.txt` 原样打印时能否成链接、点开是否是服务器文件，记下结果（上游行为）。
4. `doc.md`：编辑器打开，切到 Markdown 预览能渲染，`img/chart.png` 显示。
5. `report.html`：A 里开一个文档预览标签渲染页面；不进编辑器源码，不开系统浏览器，不切工作区。
6. `site.html`：文档预览出现「这个预览想读取 `~/pages` 里的文件」，点允许后 CSS 和图片出现；`leak.css` 在资源失败列表里，页面拿不到内容。
7. `huge.html`：文档预览显示「太大」。
8. A 的终端里点 B 的文件 `~/wt/lib/src/index.ts`（或任意文本文件）：在 A 里只读打开，B 不被激活。重启应用，A 里的这个标签还在，内容能读，没有挪到 B。
9. A 的终端里点 B 里的 HTML：A 里开文档预览。
10. 点 B 的根目录路径：仍然激活 B（上游行为）。
11. A 的 agent 对话（原生对话）里同样的绝对路径链接：结果和 1、4、5、8 一致。
12. A 里任意浏览器页的地址栏粘贴 `~/pages/report.html` 的绝对路径，或 `file:///home/<u>/pages/report.html`：转成文档预览，内容来自服务器。
13. 点 `~/notes`（目录）：提示是主机上工作区外的文件夹，不打开 Mac 上的东西；点不存在的 `~/nope.txt`：提示主机上找不到。
14. 开着 `report.html` 的文档预览重启应用：预览重新从服务器读出。
15. 本地 Mac 工作区：本地 HTML 仍按链接路由设置（系统浏览器或应用内页）；点另一个本地工作区的文件仍切过去（上游行为）。
16. 如有配对客户端或手机：工作区外文件现在能打开（上游 #33958 恢复后的行为）。
